  • 代驾项目 第二版（个人项目）

    （1）针对 v1 的分布式事务可靠性、长连接稳定性、存储耦合三大痛点做升级：
    分布式事务：以 ShardingSphere-JDBC 5.5.1 + Seata 2.5.0 替换 ShardingSphere-Proxy + tx-lcn，在保留分库分表集群可用性的前提下，完成 SJ 与 Seata 的集成适配（解决 DataSource 二次包装、DataSourceMeta 元数据解析等兼容性问题），事务异常定位时间从小时级降至分钟级，并避免了 tx-lcn 的性能抖动。
    （2）位置推送链路：司机位置传输由纯 HTTP 轮询重构为 WebSocket 为主 + HTTP 轮询降级兜底的混合方案，并独立出 WebSocket 微服务作为独立 BFF 层——主连接异常时自动降级、无感知切换，WebSocket与传统SSM Http接口解耦后可独立横向扩展，消息延迟与服务器连接压力显著下降。
    （3）Redis 存储分层：按状态特性将缓存划分为三类——会话/凭证、无状态数据（司机位置、接单设置）、有状态数据（订单接取缓存、司乘订单锁、Geo 下单数据），并通过约束"每个业务微服务至多接入一类 Redis"硬性隔离存储边界，避免跨域数据互相污染，服务拆分与扩容更干净。
